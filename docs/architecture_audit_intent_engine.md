# Architecture Audit & Refactor Plan: Intent Engine & Experience Learning

## 1. Executive Findings: Phase 0 Audit

### 1.1 Root Cause of Scope Violation in `hydrameda-hmac-integration-002`
In `hydrameda-hmac-integration-002`, the user explicitly requested:
> "Create a secure HMAC-SHA256 token signer and verifier with pytest tests. Follow the existing repository architecture. Use HMAC-SHA256 directly; do not implement JWT, claims, or unrelated authentication features."

The system failed to preserve intent due to four architectural failure modes:
1. **Unconstrained Context Injection**:
   - `ObsidianRAG` performed vector search against all markdown files in `ObsidianVault/Specs/`. It retrieved `Specs/bench-seceval-002.md`, which defined a complete JWT authentication engine (`encode_jwt`, `decode_jwt`, `validate_jwt`, claims).
   - `FileSelector` in `code_engine` scanned repository files for lexical matches on words like `token` and `verifier`. It selected `exported_modules/jwt_validator.py` and passed it as "Relevant Existing Repository Files".
   - The architect prompt concatenated these raw files under `Relevant Obsidian Notes` and `Relevant Existing Repository Files`.
2. **Absence of Canonical Intent Ledger**:
   - The original user prompt was stored only as a raw string `user_prompt` in `HydramedaState`.
   - Downstream nodes (`node_architect`, `node_prompt_optimizer`, `node_repair_agent`) did not operate against a typed, immutable constraint ledger with strict precedence.
3. **Precedence Inversion**:
   - The LLM treated retrieved context (historical task specs) as equal or higher authority than the user's negative constraints.
   - LLMs suffer from "seduction by example": when provided with a detailed implementation pattern (JWT) in context, the model will reproduce that pattern even when instructed not to.
4. **Heuristic Prompt Optimization Leakage**:
   - `node_prompt_optimizer` scanned `prompt_lower` for keywords like `jwt`. Because the prompt said "Do not implement JWT", the optimizer interpreted this as `jwt` being a requested package and declared it to the coder!

## 2. Target Architecture: `intent_engine` Subsystem

### 2.1 Subsystem Structure
```
intent_engine/
├── __init__.py                # Public exports
├── models.py                  # StructuredIntent, RequirementItem, RequirementType, ConstraintPriority
├── policy.py                  # Precedence policy (Prohibition > Requirement > Scope > Context)
├── intent_parser.py           # NLP/Regex extraction of structured requirements & evidence
├── constraint_normalizer.py   # Normalization, ID generation, priority assignment
├── constraint_compiler.py     # Compiles raw prompt into immutable StructuredIntent ledger
├── constraint_validator.py    # Deterministic artifact validation (spec, code, diff) against ledger
└── intent_guard.py            # Context filter suppressing context items that violate intent
```

### 2.2 Precedence Policy (Requirement 1.2)
1. **Priority 1 (`EXPLICIT_PROHIBITION`)**: User negative constraints (`do not implement JWT`, `no claims`, `no stubs`). Cannot be overridden by any lower priority.
2. **Priority 2 (`EXPLICIT_REQUIREMENT`)**: User positive capabilities (`HMAC-SHA256 token signer`, `token verifier`).
3. **Priority 3 (`USER_SCOPE_BOUNDARY`)**: Explicit boundaries (`modify only files required for this task`).
4. **Priority 4 (`ACCEPTANCE_CRITERIA`)**: Test suites, signature verification rules, return types.
5. **Priority 5 (`REPOSITORY_COMPATIBILITY`)**: Repository coding standards, error hierarchies, import structures.
6. **Priority 6 (`RETRIEVED_EXPERIENCE`)**: Learned engineering lessons (e.g. constant-time compare, avoid shadowing).
7. **Priority 7 (`RAG_SUGGESTION`)**: Retrieved architectural notes and documentation.
8. **Priority 8 (`MODEL_ASSUMPTION`)**: Default fallback inferences generated by LLMs.

### 2.3 Integration Plan
1. Implement `intent_engine/` with comprehensive unit and property tests.
2. Integrate `StructuredIntent` into `HydramedaState` as an immutable or controlled-update field.
3. Replace raw RAG and FileSelector injection with `IntentGuard.filter_context(...)`, ensuring that context containing prohibited symbols is filtered or redacted before reaching the architect.
4. Maintain full backwards compatibility with `langgraph_engine/fidelity.py` and ensure all 123 tests pass.
